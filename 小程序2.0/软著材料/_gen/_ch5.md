## 5.1 功能模块总览

本系统由微信小程序客户端、Node.js（Express）服务端、PHP（ThinkPHP）Web 管理后台与 Python（FastAPI + LangGraph）智能客服 Agent 四部分协同构成，功能模块覆盖"客户自助服务—后台运营管理—智能辅助决策"全链路。各功能模块总览如下：

| 分组 | 主要功能模块 |
| --- | --- |
| 客户端（小程序 + Node 后端） | 用户登录与认证、个人中心、地址与单位管理、设备管理、AI 故障自检、智能客服、维修下单、回收流程与估价、报价与确认、维修进度反馈、维修记录、微信支付、订单评价、售后管理、通知与消息推送 |
| 管理端（Node admin / super-admin） | 管理员登录与工作台、订单/工单管理、用户管理、设备类型管理、价格管理、配件与库存管理、数据统计与看板、配送分配、人工客服后台、系统设置、权限控制 |
| Web 管理后台（PHP CMMS） | 登录与 RBAC 权限、设备台账管理、工单全生命周期管理、维修人员与排班管理、巡检管理、保养计划管理、维修业务管理、支付与发票管理、进销存管理、统计报表、知识库与向量检索、营销引流、通知中心、mini-admin 小程序后台 |
| 智能客服 Agent（Python） | 智能体工作流（LangGraph）、RAG 知识库检索 |

## 5.2 角色—功能权限映射

系统采用 RBAC（基于角色的访问控制）权限模型，将 user（客户）、internal（内部人员）、admin（维修管理员）、super_admin（超级管理员）四类角色与功能模块做矩阵映射。服务端在接口层通过 auth 与 adminAuth 中间件强制校验角色，前端则按角色动态渲染菜单与入口；客户端与管理端复用同一套接口，仅通过令牌所携带的角色区分访问范围，形成"接口强制 + 前端引导"的双层权限防线。Web 管理后台（PHP）另设独立账号体系与独立 JWT，通过 roles / permissions / role_permissions 三表实现细粒度权限分配。

## 5.3 客户端功能模块

客户端功能模块以微信小程序为载体，面向客户与内部人员，提供从登录认证、设备管理、故障诊断、智能咨询到维修/回收下单、报价确认、支付、进度跟踪、评价与售后的完整自助服务闭环。

### 5.3.1 用户登录与认证

#### 5.3.1.1 微信授权登录
用户首次进入小程序触发微信授权登录：前端调用 `wx.login` 获取临时登录凭证 code，将 code 提交至后端 `POST /api/user/login` 接口；后端据此调用微信开放平台 `jscode2session` 接口，用 code 换取该用户在小程序内的唯一身份标识 openid。

#### 5.3.1.2 用户身份换取
后端以 openid 为主键查询 users 表，若用户不存在则自动创建新账号，存在则更新最近登录时间，实现"一次授权、静默登录"，无需用户输入账号密码。

#### 5.3.1.3 新用户自动注册与老用户绑定
注册与绑定在登录接口内原子完成：新 openid 触发 INSERT 建立用户记录并初始化角色为 user，老用户则 UPDATE 登录时间，随后统一进入令牌签发环节。

#### 5.3.1.4 头像获取
资料补全层通过 `button open-type="chooseAvatar"` 触发微信头像选择器，用户从微信头像库选择头像后，前端拿到临时头像文件路径，用于后续上传。

#### 5.3.1.5 昵称获取
通过 `input type="nickname"` 输入框一键回填当前微信昵称，用户可保留或修改，减少手动输入成本。

#### 5.3.1.6 头像压缩上传保存
头像文件经 multer 接收后由 sharp 压缩（限制尺寸与体积），再写入 `uploads/avatars` 目录，返回访问 URL 并写回 users 表的 avatar 字段，实现头像的持久化保存。

#### 5.3.1.7 JWT 令牌签发
登录成功后，服务端使用 jsonwebtoken 签发 JWT，payload 中携带 userId、openid 与 role，并设置有效期；令牌随登录响应返回前端，作为后续所有接口的身份凭证。

#### 5.3.1.8 JWT 令牌验证
auth.js 中间件从请求头 `Authorization: Bearer <token>` 中提取令牌，校验签名与有效期，解析出用户身份并注入 req.user；令牌缺失或失效时返回 401，前端据此自动跳转登录页。

#### 5.3.1.9 角色分流与登录态管理
登录成功后按角色分流：user/internal 进入客户端首页，admin/super_admin 进入管理后台。app.js 提供 checkLoginStatus、logout 等方法维护全局登录态，api.js 统一拦截 401 并清除失效令牌。

### 5.3.2 个人中心与资料管理

#### 5.3.2.1 个人资料展示
"我的"页面聚合展示头像、昵称、手机号与角色身份，数据来源于 `GET /api/user/info` 接口，进入页面时异步加载。

#### 5.3.2.2 个人资料编辑
profile-edit 页面支持编辑昵称、头像、手机号等资料，提交调用 `PUT /api/user/info` 持久化到 users 表，编辑结果实时回显到个人中心。

#### 5.3.2.3 头像上传
头像更换复用 5.3.1.6 的 multer + sharp 上传链路，上传成功后更新本地缓存与服务器头像地址。

#### 5.3.2.4 账号注销与用户协议
"设置"中提供账号注销入口，调用 `DELETE /api/user/delete-account` 注销账号；同时提供用户协议与隐私政策的查看入口，规范合规运营。

### 5.3.3 地址与单位管理

#### 5.3.3.1 收货地址增删改查
address / address-edit 页面提供收货地址的列表、新增、编辑与删除，数据经 addressRoutes 的 CRUD 接口持久化到 user_addresses 表，字段含联系人、电话、详细地址。

#### 5.3.3.2 默认地址设置
支持将某一地址设为默认（`POST /api/addresses/:id/default`），下单时自动带入默认地址，减少重复填写。

#### 5.3.3.3 企业单位增删改查
units / unit-edit 页面提供企业单位（收货单位）的新增、编辑、删除与默认设置，数据写入 user_units 表，适用于企业批量送修场景。

#### 5.3.3.4 默认单位设置
支持标记默认单位，下单选择"单位"服务方式时自动填充，提升企业客户的填写效率。

#### 5.3.3.5 地图选点与定位
map-picker 页面集成高德地图能力，支持关键字搜索、定位、地理编码（geocode）与逆地理编码（regeocode），用户可在地图上选点自动回填地址坐标，接口封装于 locationRoutes。

### 5.3.4 设备管理

#### 5.3.4.1 设备绑定
device-edit 页面支持手动添加常用设备，录入设备类型、品牌、型号、序列号、成色等信息，数据写入 user_devices 表，作为后续下单的快捷来源。

#### 5.3.4.2 设备档案维护
my-devices 页面展示设备列表（区分维修/回收用途），支持编辑、删除与设为默认设备，单用户设备数量上限 10 台。

#### 5.3.4.3 拍照识别型号
scan 页面调用 `wx.chooseImage` 拍照或从相册取图，上传至 `POST /api/scan/identify` 接口，后端经 AI 视觉识别返回型号候选，用户确认后自动添加到设备管理或预填下单表单。

#### 5.3.4.4 设备售后总览
device-detail 页面调用 afterSalesApi 获取设备售后总览，展示质保状态、历史维修履历与保养建议，帮助用户了解设备全生命周期信息。

#### 5.3.4.5 质保维修入口
质保期内的设备提供质保维修入口，关联原订单发起维修时可免检测费（applyWarranty），提升售后体验。

### 5.3.5 AI 故障自检

#### 5.3.5.1 四步诊断向导
diagnose 页面采用四步向导式交互：第一步选择设备类型（10 类），第二步选择品牌，第三步选择故障现象，第四步补充故障详情，引导用户结构化描述故障。

#### 5.3.5.2 品牌/故障自定义输入
品牌与故障现象除预设字典外均支持自定义输入，覆盖冷门设备与非常见故障，避免因字典不全导致无法提交。

#### 5.3.5.3 大模型故障分析
诊断信息提交至 `POST /api/diagnose/analyze`，后端构造结构化提示词调用 DeepSeek 大模型，解析返回诊断结论、可能原因（含概率）、维修建议与预估费用，以卡片形式呈现给用户。

#### 5.3.5.4 诊断结果转下单/转客服
诊断结果支持一键跳转维修下单（预填设备与故障信息）或转人工客服进一步咨询，打通"诊断—下单—咨询"链路。

### 5.3.6 智能客服

#### 5.3.6.1 多智能体意图路由
客服消息发送至 `POST /api/chat/message`，后端 routerAgent 识别用户意图，将请求分发至 faqAgent（知识库问答）、queryAgent（订单/报价查询）、repairRecycleAgent（维修/回收咨询）等专业智能体处理。

#### 5.3.6.2 知识库问答
faqAgent 调用 `POST /api/knowledge/retrieve` 进行 RAG 检索，从知识库中召回相关条目并结合大模型生成回答，覆盖常见问题与维修知识。

#### 5.3.6.3 快捷短语与建议动作
客服界面提供快捷短语（如"营业时间""维修流程"）与建议动作按钮，点击即可触发对应问答或跳转，降低用户输入成本。

#### 5.3.6.4 语音转文字
支持按住录音发送语音，音频上传至 `POST /api/chat/transcribe`，经阿里云 DashScope ASR 转写为文字后进入消息流，需获取麦克风权限（scope.record）。

#### 5.3.6.5 转人工客服
当智能体无法解决时，用户可发起转人工（`POST /api/chat/transfer-to-human`），前端轮询 `GET /api/chat/human-status` 获取人工在线状态，转接成功后进入人工会话。

#### 5.3.6.6 预约维修
客服会话内提供"预约维修"按钮，用户可直接发起维修预约，预约信息带入下单流程，实现"咨询即预约"。

#### 5.3.6.7 会话历史管理
会话与消息经 chatPersistenceRoutes 持久化到 chat_conversations 与 chat_messages 表，支持会话列表、按日期分组、删除会话与清空历史。

#### 5.3.6.8 上下文带入下单
客服或诊断结果中的设备、故障信息可构建上下文，一键带入维修下单表单，避免重复填写，缩短服务路径。

### 5.3.7 维修下单

#### 5.3.7.1 多步骤下单表单
repair 页面采用分步式表单，步骤条展示"设备→品牌型号→故障→服务安排→确认"进度，每步校验通过后方可进入下一步。

#### 5.3.7.2 设备/品牌/型号选择
设备类型、品牌、型号来自 device_types、brands 字典表，支持自定义输入补充字典外设备，前端提供级联选择提升录入效率。

#### 5.3.7.3 故障现象选择与补充描述
故障现象提供常用选项，并支持补充文字描述，帮助维修人员提前了解故障，提升报价准确性。

#### 5.3.7.4 图片上传
故障图片经 multer 上传并由 sharp 压缩后持久化到 uploads 目录，订单关联图片 URL，便于维修人员远程判断。

#### 5.3.7.5 服务方式选择
支持"到店"与"上门"两种服务方式，上门服务时展开地址与单位选择，满足不同场景需求。

#### 5.3.7.6 地址与单位关联
上门订单可关联已保存的收货地址或企业单位，自动带入联系人与地址信息，减少重复录入。

#### 5.3.7.7 估价展示
提交前展示预估维修价格（基础价 × 费率），让用户对费用有预期，体现"透明定价"的服务理念。

### 5.3.8 回收流程与估价

#### 5.3.8.1 回收品类浏览
recycle 页面提供 12 类回收品类（手机、电脑、平板、穿戴、显示器、数码、相机、游戏、无人机、服务器、网络设备、显卡）的浏览入口，数据来自 recycleData.js。

#### 5.3.8.2 品牌型号选择与搜索
支持按品牌、型号逐级选择，并提供全局模糊搜索（含搜索历史，本地存储），快速定位目标设备。

#### 5.3.8.3 回收估价问答
recycle-guide 页面以问答式选配（成色、配置等）收集设备状态，为估价计算提供输入参数。

#### 5.3.8.4 本地估价计算与价格区间
前端通过 calculateLocalEstimate 根据选配项本地计算估价，并给出价格区间，让用户即时了解回收价格。

#### 5.3.8.5 回收下单
确认估价后提交回收订单，选择地址、上传图片，调用 createRecycleOrder 生成回收订单，进入独立回收流程。

### 5.3.9 报价与确认

#### 5.3.9.1 管理员提交报价
维修管理员对待处理订单录入报价金额、说明与报告文件，订单进入 quoted（待确认报价）状态，报价全程留痕。

#### 5.3.9.2 用户查看报价明细
用户在订单详情页查看报价金额、说明与附件，明细清晰可查，体现报价透明。

#### 5.3.9.3 用户接受报价
用户确认接受报价（`PUT /api/orders/:orderId/accept-quote`），订单流转至 confirmed 状态并进入支付环节。

#### 5.3.9.4 用户拒绝报价
用户可拒绝报价并填写原因（`reject-quote`），订单回到 pending 状态由管理员重新报价，拒绝记录可追溯。

### 5.3.10 维修进度反馈与进度申请

#### 5.3.10.1 进度百分比上报
维修管理员通过进度反馈模块更新维修进度百分比，用户端实时可见维修进展。

#### 5.3.10.2 进度图片上传
支持上传进度图片（单次 ≤9 张），写入 order_progress_photos 表，直观展示维修过程。

#### 5.3.10.3 进度视频上传
支持上传进度视频（单文件 ≤100MB），写入 order_progress_videos 表，满足复杂维修场景的展示需求。

#### 5.3.10.4 进度时间线展示
progress-feedback 页面以时间线形式展示订单进度节点，文字、图片、视频按时间排序，用户一目了然。

#### 5.3.10.5 进度申请提交与审批
用户对维修中订单可提交进度申请（配件等待/维修中/测试中/其他），管理员在后台审批通过或拒绝，规范特殊进度变更。

### 5.3.11 维修记录

#### 5.3.11.1 维修节点记录
repair-records 页面记录单笔订单的维修节点（接单、检测、维修、测试、完成五阶段），操作人与时间全程留痕。

#### 5.3.11.2 配件清单记录
维修记录中登记更换配件清单，写入 repair_records 表，便于用户了解维修明细与费用构成。

### 5.3.12 微信支付

#### 5.3.12.1 创建支付单
用户确认报价后调用 `POST /api/pay/create`，wechatPayService 基于微信支付 API V3 完成 JSAPI 下单与 RSA-SHA256 签名，返回支付参数。

#### 5.3.12.2 支付结果查询
提供 `GET /api/pay/query/:orderId` 查询支付状态，前端轮询或跳转返回后查询，确保支付结果准确落库。

#### 5.3.12.3 支付回调验签
`POST /api/pay/notify` 接收微信异步通知，验签通过后更新订单支付状态，保证交易安全可靠。

#### 5.3.12.4 退款申请与退款回调
支持退款申请（`POST /api/pay/refund/apply`）与退款异步通知，退款状态同步更新订单，覆盖取消订单等场景。

#### 5.3.12.5 内部人员免付款订单
内部人员（internal 角色）下单可标记为免付款（waived），经管理员确认后无需在线支付，满足内部送修场景。

### 5.3.13 订单评价

#### 5.3.13.1 星级评分与快捷标签
订单完成后用户可进行 1~5 星评分，并按评分展示对应快捷标签（如"服务专业""响应及时"），一键点选提升评价效率。

#### 5.3.13.2 图文评价提交
支持文字评价与图片评价（≤3 张），提交调用 submitReview 写入 order_reviews 表，评价结果供后续用户参考。

#### 5.3.13.3 待评价自动过期
订单完成后 3 天未评价自动转为已完成，避免待评价状态长期滞留。

### 5.3.14 售后管理

#### 5.3.14.1 售后申请提交
用户对已完成订单可发起售后申请，经 afterSalesRoutes 提交至 after_sales_requests 表，进入售后受理流程。

#### 5.3.14.2 售后受理与状态流转
管理员受理售后申请并进行状态流转（受理/处理/解决/拒绝），用户端可实时查看售后进展。

#### 5.3.14.3 质保/维保查询
提供质保与维保查询接口（`GET /api/after-sales/warranty/order/:orderId` 等），用户可查询订单质保状态。

#### 5.3.14.4 设备维保建议
结合设备使用数据提供维保与换新建议（`GET /api/after-sales/advice/:deviceId`），提升设备管理水平。

### 5.3.15 通知与消息推送

#### 5.3.15.1 订阅消息
支持订阅消息设置（checkSubscription / manageSubscription），用户可分别开关订单、进度、报价三类通知，通知偏好持久化保存。

#### 5.3.15.2 未读角标
自定义 tabBar 与"我的"页面展示待确认报价数（quotedCount）与未读进度数（progressUnreadCount）角标，实时提示用户待办。

#### 5.3.15.3 进度未读列表
提供进度未读列表接口，用户进入订单后标记已读（progress-read），保证消息不遗漏。

## 5.4 管理端功能模块

管理端功能模块内嵌于小程序，面向维修管理员与超级管理员，提供订单处理、用户/设备/价格管理、进度审批、配送分配、数据统计与人工客服等运营管理能力。

### 5.4.1 管理员登录与工作台

#### 5.4.1.1 管理员手机号登录
管理员通过 admin-login 页面以手机号登录（`POST /api/admin/login`），区别于客户微信登录，登录成功后进入管理后台。

#### 5.4.1.2 工作台与待办角标
admin 首页为工作台，展示待处理工单与待确认报价角标（`GET /api/admin/pending-count`），帮助管理员快速定位待办。

#### 5.4.1.3 管理入口角色控制
管理入口仅对 admin / super_admin 角色可见，前端根据角色标识动态控制入口显示，防止普通用户误入。

### 5.4.2 订单/工单管理

#### 5.4.2.1 订单列表与状态筛选
admin-orders 页面提供订单列表与状态筛选（待处理/待确认报价/维修中/已完成等），支持快速检索目标订单。

#### 5.4.2.2 订单详情查看
管理员可查看订单全量信息（设备、故障、地址、报价、进度），为接单与报价提供依据。

#### 5.4.2.3 订单状态流转
管理员通过 adminRoutes 驱动订单状态流转：接单（accept）、开始处理（process）、完成（complete）、取消（cancel），状态变更实时同步用户端。

#### 5.4.2.4 订单分配
order-assign 页面支持将订单指派给具体维修人员，明确责任分工，提升维修协同效率。

#### 5.4.2.5 代客下单
管理员可代客下单（createOrderByAdmin），生成待支付订单后由用户补充地址并确认支付，覆盖线下咨询场景。

#### 5.4.2.6 订单退款处理
管理员可对订单发起退款（refund），退款流程走微信支付退款通道，状态同步更新订单。

### 5.4.3 用户管理

#### 5.4.3.1 用户列表
admin-users 页面展示用户列表，支持按手机号、昵称检索，掌握用户规模与画像。

#### 5.4.3.2 角色分配
管理员可调整用户角色（user/internal/admin/super_admin），实现内部人员授权与权限下放。

#### 5.4.3.3 禁用/启用
支持禁用或启用用户账号，禁用后用户无法登录下单，保障平台秩序。

### 5.4.4 设备类型管理

#### 5.4.4.1 设备类型（产品目录）增删改查
admin-devices 页面维护设备类型（产品目录），新增、编辑、删除设备品类，数据写入 device_types 表，供下单与诊断使用。

#### 5.4.4.2 品牌字典维护
同步维护 brands 品牌字典，保持设备类型与品牌数据一致，支撑前端级联选择。

### 5.4.5 价格管理

#### 5.4.5.1 维修价格维护
admin-prices 页面维护维修价格（prices 表），支持按品类/项目设定价格，供估价与报价参考。

#### 5.4.5.2 报价标准配置
配置报价标准与费率，使维修估价计算有据可依，体现透明定价。

### 5.4.6 配件与库存管理

#### 5.4.6.1 配件新增/编辑/删除
管理员可维护配件清单（addPart/editPart/deletePart），登记配件名称、型号与价格，写入 parts_inventory 表。

#### 5.4.6.2 配件出入库
记录配件出入库流水（stock_records），实时反映库存变动，支撑维修用料管理。

#### 5.4.6.3 库存预警
当配件库存低于阈值时触发预警，提醒管理员及时补货，避免维修延误。

### 5.4.7 数据统计与看板

#### 5.4.7.1 仪表盘统计
admin-stats 页面调用 `GET /api/admin/dashboard-stats` 聚合订单量、用户数、营收等核心指标，以卡片与图表呈现。

#### 5.4.7.2 收入趋势图
展示收入趋势曲线，直观反映经营状况，辅助运营决策。

#### 5.4.7.3 订单进度分布
统计各状态订单数量分布，帮助管理员掌握维修产能与积压情况。

### 5.4.8 配送分配

#### 5.4.8.1 配送员管理
维护配送人员信息（delivery_persons 表），作为上门取件订单的配送资源池。

#### 5.4.8.2 配送分配
delivery-assign 页面对上门订单分配配送员并设定配送费，订单进入待配送队列。

#### 5.4.8.3 配送状态跟踪与配送费
跟踪配送状态（待分配→已取件→完成），用户端可见配送进度，配送费计入订单结算。

### 5.4.9 人工客服后台

#### 5.4.9.1 会话列表（活跃/全部）
adminservice 页面展示人工客服会话列表，区分活跃与全部会话，支持按状态检索。

#### 5.4.9.2 会话认领
管理员可认领待处理会话（claimConversation），认领后进入一对一服务，避免多人重复响应。

#### 5.4.9.3 实时聊天
adminservice-chat 页面通过 WebSocket（connectAdminSocket）与用户实时聊天，消息经 socketHub 路由，支持语音转文字。

### 5.4.10 系统设置

#### 5.4.10.1 系统参数配置
admin-settings 页面配置系统参数（system_config 表），如服务时段、通知开关等，实现运营参数化管理。

### 5.4.11 权限控制

#### 5.4.11.1 RBAC 接口级校验
auth.js 校验 JWT 有效性并解析用户身份，adminAuth.js 进一步校验 admin/super_admin 角色，越权访问返回 403，实现接口级强制权限控制。

#### 5.4.11.2 前端角色控制
前端根据角色标识动态渲染菜单与操作入口，隐藏无权访问的功能，形成"接口强制 + 前端引导"的双层防线。

## 5.5 Web 管理后台功能模块

Web 管理后台基于 PHP（ThinkPHP 8.1）构建，面向企业设备资产维护与维修运营场景，提供设备台账、工单全生命周期、维修人员排班、巡检保养、维修业务、支付进销存、统计报表、知识库与营销引流等完整管理能力，是系统的资产管理中枢。

### 5.5.1 登录与 RBAC 权限管理

#### 5.5.1.1 账号密码登录
后台采用账号密码登录（auth 路由），密码经 bcrypt 加盐哈希存储，登录成功后签发 JWT 令牌，保障后台访问安全。

#### 5.5.1.2 access/refresh 双令牌 JWT
采用 access token + refresh token 双令牌机制，access token 短期有效用于接口鉴权，refresh token 用于续期，兼顾安全与体验。

#### 5.5.1.3 用户管理
提供后台用户的新增、编辑、禁用与删除，统一管理后台操作人员账号。

#### 5.5.1.4 角色/权限管理
通过 roles、permissions、role_permissions 三表实现 RBAC，可自定义角色并分配菜单/接口权限，权限校验由 PermissionCheck 中间件强制执行。

### 5.5.2 设备台账管理

#### 5.5.2.1 设备分类管理
维护设备分类（device_categories），建立统一的设备分类体系，支撑设备台账的规范化管理。

#### 5.5.2.2 设备档案管理
维护设备档案（devices），记录设备编号、名称、型号、位置、状态等信息，形成企业设备资产台账。

#### 5.5.2.3 设备详情与状态
查看设备详情与运行状态，关联历史工单与保养记录，掌握设备全生命周期状况。

### 5.5.3 工单全生命周期管理

#### 5.5.3.1 工单创建
支持创建维修工单（work_orders），关联设备、故障描述与优先级，作为维修任务的最小单元。

#### 5.5.3.2 工单指派/接单
工单可指派给维修人员，维修人员接单后进入处理环节，明确任务归属。

#### 5.5.3.3 工单处理与开始
维修人员开始处理工单，更新处理进度与维修记录，实现工单过程留痕。

#### 5.5.3.4 工单完成与验收
维修完成后提交验收，管理员验证通过后进入关闭环节，确保维修质量。

#### 5.5.3.5 工单关闭与日志
工单关闭后归档，全程操作写入 work_order_logs，支持追溯与审计。

### 5.5.4 维修人员与排班管理

#### 5.5.4.1 维修人员管理
维护维修人员信息（engineers），登记技能、状态等属性，作为工单指派的人员基础。

#### 5.5.4.2 人员推荐与绩效
提供维修人员可用性判断、任务推荐与绩效统计，优化派工决策。

#### 5.5.4.3 排班管理
维护维修人员排班（schedules），合理安排工作时间，支撑工单按时处理。

#### 5.5.4.4 排班查询
提供排班查询视图，管理员可查看人员值班情况，便于调度安排。

### 5.5.5 巡检管理

#### 5.5.5.1 巡检任务下发与执行
下发巡检任务（inspection_tasks），维修人员按计划执行并回填巡检结果，实现设备预防性检查。

### 5.5.6 保养计划管理

#### 5.5.6.1 保养计划制定
制定设备保养计划（maintenance_plans），设定保养周期与保养项目，实现设备定期维护。

#### 5.5.6.2 保养记录
记录保养执行情况（maintenance_records），沉淀设备保养历史，辅助设备健康评估。

#### 5.5.6.3 保养到期提醒
当设备临近保养周期时触发提醒，通知相关人员及时保养，避免设备故障。

### 5.5.7 维修业务管理

#### 5.5.7.1 报价单管理
管理维修报价单（quotation_orders / quotation_items），支持提交、接受、拒绝报价，报价明细可追溯。

#### 5.5.7.2 维修合同与模板
维护维修合同（repair_contracts）与合同模板（contract_templates），支持 PDF 合同生成，规范维修商务流程。

#### 5.5.7.3 检测报告
生成检测报告（test_reports），记录设备检测结论，为维修方案提供依据。

#### 5.5.7.4 维修报告
生成维修报告（repair_reports），汇总维修过程与结果，形成可交付文档。

#### 5.5.7.5 维修提醒
维修提醒（repair_reminders）通过邮件等方式通知相关方维修进度，提升沟通效率。

### 5.5.8 支付与发票管理

#### 5.5.8.1 转账支付
支持转账支付（transfer payments）的登记、确认与取消，覆盖线下对公结算场景。

#### 5.5.8.2 在线支付
对接在线支付渠道（cmms_online_payments），记录在线支付流水，与订单关联。

#### 5.5.8.3 退款
支持在线支付退款操作，退款状态同步更新，保障资金安全。

#### 5.5.8.4 发票开具/作废
管理发票（cmms_invoices）的开具与作废，规范财务票据管理。

### 5.5.9 进销存管理

#### 5.5.9.1 配件管理
维护配件（spare_parts）信息，登记配件名称、规格与库存，作为维修用料基础。

#### 5.5.9.2 配件出入库
记录配件出入库流水（stock_records），实时反映库存变化，支撑维修用料管理。

#### 5.5.9.3 库存预警
当配件库存低于阈值时触发库存预警，提醒及时补货，避免影响维修进度。

#### 5.5.9.4 供应商管理
维护供应商（suppliers）信息，管理配件采购渠道，支撑供应链协同。

### 5.5.10 统计报表

#### 5.5.10.1 收入/开支统计
统计收入与开支（statistics_income_records / statistics_expense_records），掌握经营盈亏状况。

#### 5.5.10.2 订单统计

#### 5.5.10.3 超时统计

### 5.5.11 知识库与向量检索

维护知识库（knowledge_base）条目，沉淀维修知识与常见问题，供检索与问答使用。

### 5.5.12 营销引流

维护成功案例（marketing_cases），展示服务能力与成果，提升品牌信任。

## 5.6 智能客服 Agent 功能模块

智能客服 Agent 基于 Python（FastAPI + LangGraph）构建，作为系统的智能大脑，通过多智能体工作流与 RAG 知识库检索，为客服问答与业务咨询提供智能化能力支撑。

### 5.6.1 智能体工作流

#### 5.6.1.1 LangGraph 状态机
采用 LangGraph 构建智能体状态机，按"初始化状态→加载用户状态→分析→回答"的节点链路组织推理流程，实现可控的对话编排。

#### 5.6.1.2 用户状态加载
从 repair 与 cmms_db 双库加载用户历史订单、设备等状态信息，为个性化回答提供上下文。

#### 5.6.1.3 场景识别
分析用户输入意图，识别所属业务场景（维修下单、库存、人员、知识库、概览、通用），决定后续路由。

#### 5.6.1.4 场景路由
根据识别结果将请求路由至对应场景节点，调用相应数据访问逻辑，实现领域化处理。

#### 5.6.1.5 回答生成
结合场景数据与大模型（DeepSeek）生成自然语言回答，返回给客服前端，完成一轮智能对话。

### 5.6.2 RAG 知识库检索

#### 5.6.2.1 知识向量化
将知识库内容分块（kb_chunks）并向量化存储，构建可语义检索的知识索引。

#### 5.6.2.2 检索增强生成
基于 DeepSeek 大模型与检索上下文实现检索增强生成（RAG），提升回答的准确性与专业性。

#### 5.6.2.3 双库数据访问
data_access 模块统一访问 repair 与 cmms_db 双库，为智能体提供跨库数据支撑，实现业务数据联动。
