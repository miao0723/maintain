
## 5.5 Web 管理后台功能模块

Web 管理后台基于 PHP（ThinkPHP 8.1）构建，面向企业设备资产维护与维修运营场景，提供设备台账、工单全生命周期、维修人员排班、巡检保养、维修业务、支付进销存、统计报表、知识库与营销引流等完整管理能力，是系统的资产管理中枢。该端采用独立账号体系与独立 JWT，通过 roles / permissions / role_permissions 三表实现细粒度 RBAC 权限控制。

### 5.5.1 登录与 RBAC 权限管理

#### 5.5.1.1 账号密码登录

**功能说明**：提供后台账号密码认证，保障后台访问安全。

**实现流程**：① 后台采用账号密码登录（auth 路由）；② 密码经 bcrypt 加盐哈希存储，绝不存明文；③ 登录成功后签发 JWT 令牌；④ 后续请求携带令牌鉴权。

**技术要点**：密码哈希校验；登录失败限流；账号状态（禁用/启用）校验。

**数据与接口**：涉及 auth 路由、后台用户表。

#### 5.5.1.2 access/refresh 双令牌 JWT

**功能说明**：以双令牌机制在安全与体验间取得平衡。

**实现流程**：① 采用 access token + refresh token 双令牌；② access token 短期有效用于接口鉴权；③ refresh token 用于过期后自动续期；④ 刷新时校验 refresh token 有效性并重签 access token。

**技术要点**：refresh token 可作废/轮换防重放；两令牌签名与有效期策略分开。

**数据与接口**：涉及令牌签发/刷新路由。

#### 5.5.1.3 用户管理

**功能说明**：统一管理后台操作人员账号。

**实现流程**：① 提供后台用户的新增、编辑、禁用与删除；② 维护账号角色归属；③ 禁用后无法登录；④ 记录账号操作日志。

**技术要点**：账号解绑/停用即时生效；超级管理员不可被轻易删除。

**数据与接口**：涉及后台用户 CRUD 接口与账号表。

#### 5.5.1.4 角色/权限管理

**功能说明**：实现细粒度的 RBAC 权限分配，控制不同后台角色的菜单与接口访问。

**实现流程**：① 通过 roles、permissions、role_permissions 三表实现 RBAC；② 可自定义角色并分配菜单/接口权限；③ 权限校验由 PermissionCheck 中间件强制执行；④ 权限变更即时影响访问。

**技术要点**：权限按"菜单 + 接口"双重分配；中间件逐请求校验。

**数据与接口**：涉及 roles / permissions / role_permissions 表及权限管理接口。

### 5.5.2 设备台账管理

#### 5.5.2.1 设备分类管理

**功能说明**：建立统一的设备分类体系，支撑设备台账规范化管理。

**实现流程**：① 维护设备分类（device_categories）；② 支持多级分类树；③ 设备档案归属于分类；④ 分类支撑统计与检索。

**技术要点**：分类树层级维护，避免循环引用；分类变更联动设备。

**数据与接口**：涉及 device_categories 表及分类管理接口。

#### 5.5.2.2 设备档案管理

**功能说明**：维护企业设备资产台账，记录设备全量信息。

**实现流程**：① 维护设备档案（devices）；② 记录设备编号、名称、型号、位置、状态、负责人等；③ 支持批量导入；④ 形成企业设备资产底账。

**技术要点**：设备唯一编号保证台账完整性；档案与工单/保养/巡检联动。

**数据与接口**：涉及 devices 表及档案 CRUD 接口。

#### 5.5.2.3 设备详情与状态

**功能说明**：提供设备全生命周期视图，辅助运维决策。

**实现流程**：① 查看设备详情与当前运行状态；② 关联历史工单与保养记录；③ 展示设备健康与维修履历；④ 支持跳转发起工单。

**技术要点**：详情聚合多类关联数据；状态实时反映运维情况。

**数据与接口**：涉及设备详情聚合接口。

### 5.5.3 工单全生命周期管理

#### 5.5.3.1 工单创建

**功能说明**：以工单承载每一起维修任务，明确维修对象与诉求。

**实现流程**：① 支持创建维修工单（work_orders）；② 关联设备、故障描述、优先级与指派人员；③ 工单编号唯一；④ 作为维修任务最小单元进入处理。

**技术要点**：工单优先级可配置；与设备、人员多表关联。

**数据与接口**：涉及 work_orders 表及工单创建接口。

#### 5.5.3.2 工单指派/接单

**功能说明**：将工单分配到具体维修人员，明确任务归属。

**实现流程**：① 工单可指派给维修人员；② 维修人员接单后进入处理环节；③ 指派/接单记录留痕；④ 未接单工单可改派。

**技术要点**：指派与接单权限分明；防止无人认领（超时提醒）。

**数据与接口**：涉及工单指派/接单接口与日志。

#### 5.5.3.3 工单处理与开始

**功能说明**：记录维修过程中的处理进度，实现过程留痕。

**实现流程**：① 维修人员开始处理工单；② 更新处理进度与备注；③ 可上传过程照片；④ 处理状态实时更新。

**技术要点**：处理记录按时间维度留存；状态随环节推进。

**数据与接口**：涉及工单进度更新接口与维修记录。

#### 5.5.3.4 工单完成与验收

**功能说明**：维修完成后进行验收，确保维修质量达标。

**实现流程**：① 维修人员提交完成；② 管理员进行验收；③ 验收通过进入关闭环节；④ 验收不通过则退回整改。

**技术要点**：验收权限与角色对应；验收结果留痕。

**数据与接口**：涉及工单验收接口与验收记录。

#### 5.5.3.5 工单关闭与日志

**功能说明**：工单关闭后归档，全程操作可追溯审计。

**实现流程**：① 工单关闭并归档；② 全程操作写入 work_order_logs；③ 支持按工单检索完整操作历史；④ 满足审计与追溯要求。

**技术要点**：操作日志只增不改；关闭后工单状态只读。

**数据与接口**：涉及 work_order_logs 表与审计查询。

### 5.5.4 维修人员与排班管理

#### 5.5.4.1 维修人员管理

**功能说明**：维护维修人员信息库，作为工单指派与排班的人员基础。

**实现流程**：① 维护维修人员信息（engineers）；② 登记技能、级别、状态等属性；③ 支撑派工与排班选择；④ 记录在岗与忙闲状态。

**技术要点**：人员技能标签支撑智能派工；状态与排班/工单联动。

**数据与接口**：涉及 engineers 表及人员管理接口。

#### 5.5.4.2 人员推荐与绩效

**功能说明**：提供派工推荐与绩效统计，优化人力调度与考核。

**实现流程**：① 综合人员技能、忙闲、历史工单提供派工推荐；② 统计工单完成量、及时率等绩效指标；③ 辅助管理决策。

**技术要点**：推荐算法综合多维特征；绩效数据来自工单统计。

**数据与接口**：涉及派工推荐逻辑与绩效统计接口。

#### 5.5.4.3 排班管理

**功能说明**：合理安排维修人员工作时间，支撑工单按时处理。

**实现流程**：① 维护维修人员排班（schedules）；② 设定工作日、班次与值班安排；③ 排班影响工单指派可用性；④ 支持按周/月制定。

**技术要点**：排班冲突校验；与人员可用性联动。

**数据与接口**：涉及 schedules 表及排班管理接口。

#### 5.5.4.4 排班查询

**功能说明**：提供排班视图，便于管理员调度查看。

**实现流程**：① 提供排班查询视图；② 按人员/时间维度展示值班情况；③ 快速定位可调度人员。

**技术要点**：视图按日历化展示，直观清晰。

**数据与接口**：涉及排班查询接口。

### 5.5.5 巡检管理

#### 5.5.5.1 巡检任务下发与执行

**功能说明**：通过计划性巡检实现对设备的预防性检查，降低故障发生率。

**实现流程**：① 下发巡检任务（inspection_tasks），关联设备与巡检项；② 指派维修人员按计划执行；③ 巡检结果（正常/异常）回填；④ 异常项联动生成维修工单。

**技术要点**：巡检项模板化；异常自动转工单。

**数据与接口**：涉及 inspection_tasks 表及巡检执行接口、异常转工单逻辑。

### 5.5.6 保养计划管理

#### 5.5.6.1 保养计划制定

**功能说明**：为设备制定周期性保养计划，实现设备的定期维护。

**实现流程**：① 制定设备保养计划（maintenance_plans）；② 设定保养周期、保养项目与责任人；③ 计划到期自动触发任务与提醒。

**技术要点**：周期可配置（月/季/年）；按设备批量制定。

**数据与接口**：涉及 maintenance_plans 表及计划管理接口。

#### 5.5.6.2 保养记录

**功能说明**：沉淀每次保养执行情况，形成设备保养历史。

**实现流程**：① 记录保养执行情况（maintenance_records）；② 保存保养项目、结果、人员、时间；③ 辅助设备健康评估。

**技术要点**：与保养计划关联；记录可追溯。

**数据与接口**：涉及 maintenance_records 表。

#### 5.5.6.3 保养到期提醒

**功能说明**：临近保养周期自动提醒，避免设备因失保而故障。

**实现流程**：① 当设备临近保养周期时触发提醒；② 通过站内通知/消息触达相关人员；③ 提醒后引导执行保养。

**技术要点**：提醒规则基于下次保养日期计算；与通知中心联动。

**数据与接口**：涉及保养到期计算与通知中心。

### 5.5.7 维修业务管理

#### 5.5.7.1 报价单管理

**功能说明**：管理维修报价全流程，规范费用确认。

**实现流程**：① 管理维修报价单（quotation_orders / quotation_items）；② 支持提交、接受、拒绝报价；③ 报价明细逐项可追溯；④ 与订单/工单关联。

**技术要点**：报价版本化留痕；接受/拒绝状态机。

**数据与接口**：涉及 quotation_orders / quotation_items 表。

#### 5.5.7.2 维修合同与模板

**功能说明**：为维修商务活动提供合同支持，规范化文档流程。

**实现流程**：① 维护维修合同（repair_contracts）与合同模板（contract_templates）；② 支持 PDF 合同生成；③ 合同与订单/客户关联。

**技术要点**：模板化生成提升效率；合同归档可查。

**数据与接口**：涉及 repair_contracts / contract_templates 表。

#### 5.5.7.3 检测报告

**功能说明**：生成设备检测报告，为维修方案与费用提供客观依据。

**实现流程**：① 生成检测报告（test_reports）；② 记录检测项目、结论与建议；③ 关联设备与工单；④ 可供打印/下载。

**技术要点**：检测模板化；报告与维修报价关联。

**数据与接口**：涉及 test_reports 表。

#### 5.5.7.4 维修报告

**功能说明**：汇总维修过程与结果，形成可交付的维修文档。

**实现流程**：① 生成维修报告（repair_reports）；② 汇总维修项目、更换配件、工时与结论；③ 面向客户交付；④ 支持导出。

**技术要点**：报告数据自动聚合维修记录；输出格式规范。

**数据与接口**：涉及 repair_reports 表。

#### 5.5.7.5 维修提醒

**功能说明**：主动触达相关方维修进度，提升沟通效率。

**实现流程**：① 维修提醒（repair_reminders）通过邮件/通知等方式通知相关方；② 在关键节点（待验收、超时预警）触发；③ 提醒记录可追溯。

**技术要点**：提醒规则按需配置；多渠道触达。

**数据与接口**：涉及 repair_reminders 表与通知渠道。

**技术要点**：到账确认需人工/对账；与财务记录关联。

**数据与接口**：涉及转账支付记录表。

#### 5.5.8.2 在线支付

**功能说明**：对接在线支付渠道，记录线上支付流水。

**实现流程**：① 对接在线支付渠道（cmms_online_payments）；② 记录支付流水、金额、渠道、状态；③ 与订单/工单关联；④ 支持支付结果查询。

**技术要点**：渠道配置化；回调验签保证可信。

**数据与接口**：涉及 cmms_online_payments 表及在线支付对接。

#### 5.5.8.3 退款

**技术要点**：退款金额校验；退款流程受权限控制。

**数据与接口**：涉及退款接口与支付记录。

#### 5.5.8.4 发票开具/作废

**功能说明**：规范财务票据的开具、作废与归档管理。

**实现流程**：① 管理发票（cmms_invoices）的开具与作废；② 关联订单与客户信息；③ 记录发票号与开票状态；④ 已作废发票标记隔离。

**技术要点**：发票号唯一；作废操作留痕。

**数据与接口**：涉及 cmms_invoices 表及发票管理接口。

#### 5.5.11.1 知识库管理

**功能说明**：沉淀维修知识与常见问题，供智能客服检索与问答使用。

**实现流程**：① 维护知识库（knowledge_base）条目；② 分类组织维修知识、FAQ；③ 供智能客服检索引用。

**技术要点**：知识条目带标签与来源；支持启停发布。

**数据与接口**：涉及 knowledge_base 表及管理接口。

#### 5.5.11.2 知识文档导入

**功能说明**：将文档导入知识库，扩充知识来源。

**实现流程**：① 支持知识文档导入（kb_files）；② 上传 PDF/Word 等文档；③ 纳入知识库处理链路。

**技术要点**：文档格式解析；导入后进入向量化流程。

**数据与接口**：涉及 kb_files 表及导入接口。

#### 5.5.11.3 向量分块

**功能说明**：将知识内容向量化分块，构建语义检索基础。

**实现流程**：① 知识文档经向量化分块（kb_chunks）；② 按语义切分并生成向量；③ 存入向量库（Milvus）。

**技术要点**：分块粒度设置影响检索质量；向量化基于 embedding 模型。

**数据与接口**：涉及 kb_chunks 与向量库。

#### 5.5.11.4 向量检索

**功能说明**：基于向量语义检索召回相关知识，支撑 RAG 智能问答。

**实现流程**：① 将用户问题向量化；② 基于 Milvus 向量库做语义相似度检索；③ 召回相关内容；④ 作为大模型 RAG 的上下文。

**技术要点**：混合检索（向量 + 关键词）提升召回；检索结果排序。

**数据与接口**：涉及 Milvus 向量库与检索接口。

## 5.6 智能客服 Agent 功能模块

智能客服 Agent 基于 Python（FastAPI + LangGraph）构建，作为系统的智能大脑，通过多智能体工作流与 RAG 知识库检索，为客服问答与业务咨询提供智能化能力支撑。Agent 可同时访问 repair 与 cmms_db 数据库，实现跨库业务数据联动。

### 5.6.1 智能体工作流

#### 5.6.1.1 LangGraph 状态机

**功能说明**：以状态机编排多智能体对话流程，实现可控的智能对话。

**实现流程**：① 采用 LangGraph 构建智能体状态机；② 按"初始化状态→加载用户状态→分析→回答"节点链路组织推理；③ 每节点处理特定职责；④ 实现可控对话编排。

**技术要点**：状态节点可复用、可扩展；流程可视化便于调试。

**数据与接口**：涉及 LangGraph 工作流定义。

#### 5.6.1.2 用户状态加载

**功能说明**：加载用户相关业务状态，为个性化回答提供上下文。

**实现流程**：① 从 repair 与 cmms_db 双库加载用户历史订单、设备等状态；② 构造问答上下文；③ 供后续回答引用。

**技术要点**：跨库聚合用户画像；上下文时效性管理。

**数据与接口**：涉及双库数据访问。

#### 5.6.1.3 场景识别

**功能说明**：识别用户输入所属业务场景，决定后续对话路由。

**实现流程**：① 分析用户输入意图；② 识别所属业务场景（维修下单、库存、人员、知识库、概览、通用）；③ 输出场景标签供路由。

**技术要点**：场景识别结合关键词 + 语义；支持多场景意图。

**数据与接口**：涉及场景识别模型与分类逻辑。

#### 5.6.1.4 场景路由

**功能说明**：按识别结果将请求路由至对应场景节点处理。

**实现流程**：① 根据场景标签将请求路由至对应节点；② 节点调用相应数据访问逻辑；③ 实现领域化处理。

**技术要点**：路由规则与场景映射可配置；未知场景走通用兜底。

**数据与接口**：涉及场景路由与请求分发。

#### 5.6.1.5 回答生成

**功能说明**：结合场景数据与大模型生成自然语言回答。

**实现流程**：① 结合场景数据与大模型（DeepSeek）生成回答；② 组织提示词与检索上下文；③ 返回自然语言回答给客服前端。

**技术要点**：大模型输出安全与合规校验；生成失败降级。

**数据与接口**：涉及大模型调用与回答返回。

### 5.6.2 RAG 知识库检索

#### 5.6.2.1 知识向量化

**功能说明**：构建可语义检索的知识索引，支撑 RAG。

**实现流程**：① 将知识库内容分块（kb_chunks）；② 向量化存储；③ 构建语义检索索引。

**技术要点**：分块策略影响检索精度；向量库选择（Milvus）。

**数据与接口**：涉及 kb_chunks 与向量化/存储流程。

#### 5.6.2.2 检索增强生成

**功能说明**：通过 RAG 提升回答准确性与专业性。

**实现流程**：① 基于 DeepSeek 大模型与检索上下文实现检索增强生成（RAG）；② 先检索后生成；③ 回答附知识来源。

**技术要点**：检索结果排序与截断；上下文窗口管理。

**数据与接口**：涉及 RAG 生成流程与大模型调用。

#### 5.6.2.3 双库数据访问

**功能说明**：为智能体提供跨库数据支撑，实现业务数据联动。

**实现流程**：① data_access 模块统一访问 repair 与 cmms_db 双库；② 按业务封装数据读取；③ 供智能体各节点调用。

**技术要点**：双库连接与事务管理；数据抽象层复用。

**数据与接口**：涉及 data_access 模块与双库数据源。
