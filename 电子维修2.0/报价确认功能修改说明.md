# 报价确认功能修改说明

## 一、功能概述

在原有订单流程中新增「报价」与「确认报价」两个步骤，使维修人员必须先报价、用户确认后才能开始维修处理。

**原流程：** `pending(待处理) → processing(维修中) → completed(已完成)`

**新流程：** `pending(待处理) → quoted(待确认报价) → confirmed(已确认报价) → processing(维修中) → completed(已完成)`

---

## 二、数据库变更

### 2.1 迁移文件

**文件：** `backend/database/migrations/20260525_add_quoted_confirmed_status.sql`

```sql
ALTER TABLE `orders` 
  MODIFY COLUMN `status` enum('pending','quoted','confirmed','processing','completed','review','cancelled') 
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci NULL DEFAULT 'pending' 
  COMMENT '订单状态';
```

### 2.2 涉及的数据库字段（orders表已有）

| 字段 | 说明 |
|------|------|
| `status` | 新增 `quoted`、`confirmed` 两个枚举值 |
| `quote_price` | 报价金额 |
| `quote_description` | 报价说明 |
| `quote_files` | 报价附件（JSON数组） |
| `quote_status` | 报价状态：`pending`/`accepted`/`rejected` |
| `quote_created_at` | 报价时间 |
| `quote_created_by` | 报价人ID |
| `quote_rejected_reason` | 拒绝原因 |

## 三、后端API变更

### 3.1 管理员路由 (`backend/routes/adminRoutes.js`)

#### (1) 新增报价接口

**接口：** `PUT /api/admin/orders/:orderId/quote`

- 允许 `pending` 或 `processing` 状态的订单提交报价
- 报价后订单状态变为 `quoted`（等待用户确认）
- 如果是 `pending` 未分配的订单，报价时自动分配给当前管理员
- 请求参数：`quote_price`（必填，>0）、`quote_description`（选填）、`quote_files`（选填，JSON数组）

```javascript
// 关键逻辑
await db.query(
  `UPDATE orders
   SET quote_price = ?, quote_description = ?, quote_files = ?,
       quote_status = 'pending', quote_created_at = NOW(), quote_created_by = ?,
       status = 'quoted',
       assigned_to = ?, assigned_at = IF(assigned_to IS NULL OR assigned_to = 0, NOW(), assigned_at),
       updated_at = NOW()
   WHERE id = ?`,
  [parseFloat(quote_price), quote_description || '', filesJson, adminId, adminId, orderId]
);
```

#### (2) 开始处理接口变更

**接口：** `PUT /api/admin/orders/:orderId/process`

- **原来：** 只允许 `pending` 状态
- **现在：** 允许 `pending` 或 `confirmed` 状态
- 错误提示改为"需要用户确认报价后才能开始处理"

```javascript
if (order[0].status !== 'pending' && order[0].status !== 'confirmed') {
  return res.status(400).json({
    success: false,
    error: '订单状态不正确，需要用户确认报价后才能开始处理'
  });
}
```

#### (3) 分配订单接口变更

**接口：** `PUT /api/admin/orders/:orderId/assign`

- **原来：** 分配后自动将状态改为 `processing`
- **现在：** 仅更新 `assigned_to`，不自动修改状态（分配后管理员需先报价）

```javascript
// 注释：分配后不自动改为处理中，被分配的管理员需要先报价
await db.query(
  `UPDATE orders SET assigned_to = ?, assigned_at = NOW(), updated_at = NOW() WHERE id = ?`,
  [targetAdminId, orderId]
);
```

### 3.2 用户路由 (`backend/routes/orderRoutes.js`)

#### (1) 新增接受报价接口

**接口：** `PUT /api/orders/:orderId/accept-quote`

- 验证订单属于当前用户且 `quote_status === 'pending'`
- 更新 `quote_status` 为 `accepted`
- 将 `quote_price` 写入 `actual_price`
- 订单状态变为 `confirmed`

```javascript
await db.query(
  `UPDATE orders
   SET quote_status = 'accepted', actual_price = quote_price,
       status = 'confirmed', updated_at = NOW()
   WHERE id = ?`,
  [orderId]
);
```

#### (2) 新增拒绝报价接口

**接口：** `PUT /api/orders/:orderId/reject-quote`

- 验证订单属于当前用户且 `quote_status === 'pending'`
- 更新 `quote_status` 为 `rejected`
- 订单状态回退为 `pending`（允许管理员重新报价）
- 请求参数：`reason`（选填，拒绝原因）

```javascript
await db.query(
  `UPDATE orders
   SET quote_status = 'rejected', quote_rejected_reason = ?,
       status = 'pending', updated_at = NOW()
   WHERE id = ?`,
  [reason || '', orderId]
);
```

#### (3) 取消订单接口变更

**接口：** `POST /api/orders/:orderId/cancel`

- **原来：** 只允许 `pending` 状态取消
- **现在：** 允许 `pending` 或 `quoted` 状态取消

```javascript
if (order.status !== 'pending' && order.status !== 'quoted') {
  return res.status(400).json({ success: false, error: '只有待处理或待确认报价的订单可以取消' });
}
```

#### (4) 订单详情接口变更

**接口：** `GET /api/orders/:id/detail`

- 返回数据新增报价相关字段：`quote_price`、`quote_description`、`quote_files`、`quote_status`、`quote_created_at`、`quote_created_by`、`quote_rejected_reason`
- 新增 `quote_files` 的JSON解析处理

### 3.3 超级管理员路由 (`backend/routes/superAdminRoutes.js`)

## 五、状态流转图

```
用户下单 → [pending] ──管理员报价──→ [quoted] ──用户接受──→ [confirmed] ──管理员开始处理──→ [processing] ──完成──→ [completed]
              │                        │                                              │
              │取消                    │取消/拒绝(回pending)                           │完成
              ↓                        ↓                                              ↓
          [cancelled]             [cancelled]/[pending]                          [completed]
```
